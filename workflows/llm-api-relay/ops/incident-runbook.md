# 事故 SOP

## R1. 上游账号被封

**触发**:`healthcheck.sh` 报 OpenAI 5xx > 50% / 持续 30 分钟

**立即动作**:
1. 切到备用账号池(脚本自动,见 `../healthcheck.sh`)
2. 通知用户(可选:不通知 / 群内发"上游微调"公告)
3. 检查上游用量,确认是否触发风控
4. 临时降级:OpenAI → Gemini / DeepSeek

**事后**:
1. 评估封号根因(账号池行为?消费异常?)
2. 重置被封账号的 IP / 节点
3. 采购新账号
4. 更新 `../compliance/risk-register.md#R1` 的"概率"

## R2. Stripe 账户被风控

**触发**:收到 Stripe 风控邮件 / 资金 hold / 账户被 review

**立即动作**:
1. **不要**继续用 Stripe 收款(会被加重怀疑)
2. 切到 Creem / Paddle / USDT
3. 通知现有 Stripe 订阅用户:"支付通道升级,需要重新绑定卡"
4. 准备申诉材料(身份证 + 公司注册证 + 业务说明)

**事后**:
1. 申诉(成功率 30-50%,通常 2-4 周回复)
2. 长期:用 Creem / Paddle 为主收通道,Stripe 作辅助

## R3. 数据泄露

**触发**:用户公开投诉 / 媒体曝光 / 监管通知

**立即动作**:
1. 立即关停服务
2. 启动数据取证(保留日志,找泄露路径)
3. 公告 + 通知所有用户
4. 评估是否需上报监管(GDPR 72h)

**事后**:
1. 修补漏洞
2. 重建服务(新数据库,迁移用户余额)
3. 评估法律风险

## R4. 监管收紧(中国)

**触发**:域名 / IP 在国内被封 / 收到监管通知

**立即动作**:
1. 切到海外节点(美西)
2. 不再接受国内 IP 用户
3. 通知老用户
4. 评估主体迁移

**事后**:
1. 转向海外客户
2. 内容做合规审查

## R5. 服务过载 / 宕机

**触发**:5xx 率 > 5% / 客户反馈"用不了"

**立即动作**:
1. 检查 healthcheck.sh 输出
2. 评估是上游问题还是本地
3. 必要时手动重启:`docker compose restart`
4. 切备用节点

**事后**:
1. 写事故报告
2. 引入更多冗余
3. 引入自动恢复(进程守护 / 健康探针)
