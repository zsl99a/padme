# 012 - OSS / 平台月检机制

## 目的

OSS 工具市场(LLM Gateway、OpenAI 兼容 API、数据库、向量库)和海外平台生态变化极快(每月新增竞品、政策更新、SDK 弃用),档案首次验证时正确,3 个月后可能已过时。本规则强制建立**月度体检**机制,确保 active 档案不因"生态已变"而沦为误导。

## 适用范围

所有 `status: active` 的机会档案,凡是涉及以下任一生态依赖:

- LLM Gateway / OpenAI 兼容 API 中转(LiteLLM / Portkey / Bifrost / OpenRouter 等)
- AI 编程工具 / Vibe Coding IDE
- 开源 SaaS 替代品(Nextcloud、Umami、Plausible 等)
- 浏览器扩展商店(Chrome MV3、Firefox Add-on 政策)
- 内容平台/电商平台(Substack、Beehiiv、Etsy、AMZ Merch、TikTok Shop、Shopify 等)
- 浏览器内置服务(只对部分浏览器/部分用户可用)
- 移动端生态(Capacitor、React Native、Expo 等)

## 具体规则

1. **每月 1 号体检**:对所有 `status: active` 档案做"上游存活检查":
   - 官方网站可访问
   - 公司仍运营
   - 收入分成/分成计划仍启用
   - 关键 URL 无 404 / 重定向
2. **OSS 市场特殊体检**:LLM Gateway / API 中转 / 数据库等 OSS 工具市场,每月有新增;体检时必须做:
   - 检索 "best X open source 2026" 类对比文章(GitHub Trending、HN、Reddit r/LocalLLaMA)
   - 检索过去 30 天新发的对比文章(如 "Top 10 LLM Gateways 2026-05")
3. **强对手出现自动降分**:月检时发现过去 30 天内出现 ≥ 1 个强对手:
   - 新对手融资 / 新对手月活 / 新对手官方公告 → 市场子项 -1
   - 新对手获权威媒体(TechCrunch / The Verge)专题报道 → 市场子项 -1.5
4. **政策突变立即复核**(见 010 规则 §3):即使未到月检日,出现以下任一情况必须立即复核:
   - 平台官方公告"重大更新" / "政策变更"
   - 媒体或社区出现"X 平台 6 月新规" / "X 平台停止 Y 业务"
5. **月检结果落档**:
   - 体检后更新档案 `last_updated` 字段
   - 体检日志记录在 `workflows/monthly-health-check.md`(待建),含:
     - 检查日期
     - 检查项(官网、新闻、竞品、SDK 版本)
     - 检查结果(通过 / 发现问题 / 已修复)
6. **失败处理**:
   - 上游已死:档案标 `archived`,从主推荐清单移除
   - 上游萎缩:标 `stale`,暂停推荐
   - 仅个别 SKU 失效:更新档案具体子项,主框架保持 `active`
7. **人工触发加速月检**:老板若发现某机会"现在做不到了",应立即提交触发该档案的加速月检,不等 1 号。
