# 005 - 自动化执行约束

## 目的

兑现用户核心要求:「AI 或者通过简单的脚本可全自动执行」。

## 适用范围

所有进入评分阶段的机会。

## 具体规则

### 1. 自动化比例计算

```
auto_ratio = 自动化可完成的步骤数 / 总步骤数
```

- 步骤定义:从「启动」到「收到第一笔钱」中间所有可识别动作(如注册、发布、提交、跟踪)。
- 每个步骤必须能回答:「这一步是 AI 决定 + 脚本执行 / AI 生成 + 人工点击 / 全人工」。

### 2. 阈值

- `auto_ratio ≥ 0.8`:**通过**。
- `0.5 ≤ auto_ratio < 0.8`:**降级**为「半自动」,分数照打但档案必须标注「半自动」。
- `auto_ratio < 0.5`:**拒绝**。

### 3. 必备的「全自动最小栈」

通过的机会必须能映射到下列工具之一:

- **LLM 流水线**(Claude / GPT-4 + 工具调用 + API)。
- **现成 SaaS 组合**(Zapier / Make / n8n / Dify / Coze / Coze 空间 / Manus 类 Agent)。
- **自写脚本**(Python / Node + cron / GitHub Actions)。

### 4. 不可全自动化的典型场景(直接拒绝)

- 真人出镜拍摄(YouTube 真人频道、TikTok 真人)。
- 需要对方平台人工审核且无 API 通知。
- 需要实名且每账号绑定唯一身份证(无可绕过路径)。

### 5. 自动化成本计入启动成本

自动化栈本身的成本(API 月费、服务器)在评分「启动成本」维度里视为可接受开销,只要 < 预期月收入的 20%。
