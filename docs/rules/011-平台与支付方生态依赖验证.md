# 011 - 平台/支付方生态依赖验证

## 目的

任何依赖"第三方平台 / 支付方 / 聚合商 / 钱包"作为收入来源的机会,都隐含"上游停业 = 机会失效"的单点风险。本规则强制在档案落档或复检时,显式验证"上游生态是否仍存活",并在依赖方萎缩时自动降分。

## 适用范围

所有 `freshness_class: structural` 或 `volatile` 机会档案,凡是收入链路涉及以下任一上游:

- 第三方支付方(钱包、聚合收款)
- 平台/聚合商(API 平台、内容平台、广告平台)
- 浏览器内置服务(只对部分浏览器/部分用户可用)
- 浏览器扩展商店(Chrome MV3 政策风险)
- SDK / 中间件依赖(开源工具链、商业 SaaS API)

## 具体规则

1. **依赖图显式化**:档案 frontmatter 加 `depends_on` 字段(可多个),列出所有上游生态:
   ```yaml
   depends_on: [coil-wallet, brave-browser-monetization]
   ```
2. **落档时必查**:新增机会或老档月检时,必须对每个 `depends_on` 项验证:
   - 官方网站仍可访问
   - 公司仍运营(无 shutdown 公告)
   - 收入分成模式仍启用(无 "we are winding down" 之类公告)
3. **30 天复查**:任何依赖"单一支付方/平台"的机会,30 天内必须复查生态状态,搜索关键词:
   - `"X shutdown"`、`"X closed"`、`"X alternative"`、`"X winding down"`
4. **依赖方失效自动降分**:
   - 主要支付方已关闭:市场子项 -2 分,风险评分 -2 分
   - 依赖方萎缩(用户基数大幅下降):市场子项 -1 分
   - 依赖方仅"分阶段停服"(如 Coil 模式):档案标 `stale` 并暂停推荐
5. **依赖方死亡但替代存在**:
   - 列出剩余主要支付方(如 Coil 死后剩 Brave 浏览器内置 Web Monetization)
   - 在档案"风险与红线"节明确"生态几近消亡,现实数据奖励无法实现"
6. **依赖方死亡且无替代**:
   - 档案标 `archived`,从主推荐清单移除
   - 在"踩坑记录"节保留案例,作为反例教材
7. **多个上游冗余**:若机会可同时挂多个支付方/平台(冗余),应在档案标注 "上游冗余度:高",降低单点失效风险评级。

## 踩坑记录

- **2026-06-05 Cluster 4 验证**(`subagent_tasks/cluster-4-ai-saas-api/result.md` §3.11 + §6.1):
  - **web-monetization-api 致命问题**:Coil 钱包(主要支付方)已关闭服务。Interledger 社区 2025 起讨论"Coil shutdown 之后",主流意见是 Web Monetization 仍在但生态萎缩。
  - **Brave 浏览器内置是剩余主要支付方,但用户基数小**:单访客 $0.5-2/月、需 100+ 月活访客才 $50-200,完全无法支撑"月入 $1k+"现实数据奖励。
  - **风险拆分**:市场风险从 5 降到 1(支付方生态几近消亡);新分从 7.4 降到 5.5(进入"观察中"档,建议进 parking-lot)。
  - **教训**:原档 Coil 钱包 2024 状态,但 2025 Coil 已关闭,档案**整年没复检**;验证时如做 30 天内 `Coil shutdown` 检索,可在原档最早写入时就发现。

- **2026-06-05 Cluster 2 验证**(`subagent_tasks/cluster-2-creator-economy/result.md` §3.7):
  - **newsletter-ghostwriting-service-2026** 引用 AGW(Association of Ghostwriters)数据、Gotham 调查、Nicolas Cole 复盘全是二手汇总(详见 014),**未验证这些"行业平台"自身是否仍是行业基准**;AGW URL 404 时整条证据链失效。
  - **教训**:二手汇总源背后可能也是"依赖方",其停业/失联时二手证据链直接断;需在依赖图里也标注二手源的可访问性。

- **2026-06-05 Cluster 4 验证**(`subagent_tasks/cluster-4-ai-saas-api/result.md` §6.1):
  - **Plaud 实际规模被低估**:原档 500K 累计出货是 2024 数字,2025/2026 实际是 1M+(Sacra 验证);依赖 Plaud 渠道的 affiliate 机会 ROI 被低估。
  - **Rezi 真实规模**:原档"Rezi 已是品类头部"无具体数字,实际 TrustMRR $273,192 MRR / $5.4M 累计营收 / 60% margin;红海竞品要查第三方营收数据库。
