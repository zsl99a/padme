# 014 - 二手汇总源标记规则

## 目的

Newsletter 教程站、博客对比站、行业排行榜、聚合站点(Readless.app、EliteWealthPlan、GramBase、GetLatka、TrustMRR 的汇总页等)是"二手汇总"——它们汇总了别人的一手数据,但自己不是来源。它们常被误用为"权威一手证据"来支撑关键政策/收入声明。本规则强制:二手源优先级 = 最低;若仅二手源,必须降"证据强度"维度 1-2 分,并显式标注"二手"。

## 适用范围

所有机会档案"参考来源"节,凡是来源类型为以下任一:

- Newsletter 教程站(readless.app、Substack Helper 等)
- 博客对比站 / 排行榜(EliteWealthPlan、Best of X 类博客)
- 行业聚合站(GramBase、SaaSHub、Crunchbase 行业页)
- 公众号/知乎/小红书等社区平台转载文章
- 媒体"行业总览"专题(无具体公司链接到原始 dashboard)
- 任何引用"Press Gazette / Reuters / NYT"但未给原始 URL 的二手转述

## 具体规则

1. **二手源前缀标签**:所有二手汇总源在档案"参考来源"节必须显式加 `[二手汇总]` 前缀:
   ```
   - [二手汇总] Readless.app Substack 8.4M 综述 — https://www.readless.app/blog/...
   ```
2. **二手源不能作唯一证据**:
   - 任何关键政策/收入声明若仅二手源,**不构成有效证据**,需配合至少 1 个一手来源(官方文档/权威媒体一手专题)
   - 仅二手源的声明,自动降"证据强度"维度 1-2 分
3. **二手源引用的权威媒体要回溯**:
   - 当二手源引用了"Press Gazette / Reuters / NYT"等权威媒体,需在档案中尝试找原始 URL
   - 若原始 URL 404,必须在二手源条目下追加注释:"原始链接 404,数据来自二手汇总"
4. **二手源过期数据更不可信**:二手汇总可能引用了多年前的原始数据;即使是 Press Gazette 2018 的旧文,经 Newsletter 二次转述到 2026,可信度更低;需在档案标 `(stale: YYYY)` 标签
5. **行业调查发布时间易错**:
   - 二手源常把"2024 Gotham 调查"误标为"2026 Q1"等近时间
   - 任何行业报告引用必须确认原始发布时间(精确到月)
6. **二手源"前 N 名"类声明处理**:
   - "前 N 名月入过万" / "X% 用户月入 $1k+" / "X 个顶尖创作者" 等声明,在二手源中常见,通常**是推测,不是数据**
   - 必须在档案"风险与红线"节标注"推测,非实测数据",并降"现实数据奖励"维度
7. **可信二手源白名单**(可作"补充证据"而非"主要证据"):
   - GetLatka(创始人本人公开收入数据,可信但需抓个人页)
   - TrustMRR(需抓具体公司 dashboard 截图,非"行业汇总"页)
   - Crunchbase / PitchBook 公司档案
   - Sacra 公司档案
8. **不可信二手源灰名单**(禁止作为主要证据):
   - Readless.app / EliteWealthPlan / GramBase 等聚合站
   - Newsletter 教程站
   - 公众号/知乎专栏
   - SEO 内容农场(Medium 大量 AI 生成内容)

## 踩坑记录

- **2026-06-05 Cluster 2 验证**(`subagent_tasks/cluster-2-creator-economy/result.md` §6 + §3.7):
  - **newsletter-ghostwriting-service-2026 引用 AGW、Gotham、Cole 案例全是二手**:3 条关键证据失效:
    - AGW(Association of Ghostwriters)URL 404,数据来自二手汇总
    - Substack Ghostwriter Directory 无独立证据,只有二手转述
    - Gotham Ghostwriters Business Survey 实际是 2024 调查,被误标为"2026 Q1"
  - **newsletter-ghostwriting-service-2026 评分从 8.06 降至 7.3**:若按本规则,AGW 数据不可信,应直接降至 6.8;档案存在"二手源被当真证据"的根本问题。

- **2026-06-05 Cluster 2 验证**(`subagent_tasks/cluster-2-creator-economy/result.md` §3.1):
  - **Substack Leaderboard 不公开收入数据**:原档引用"前 N 名月入过万"是推测;Press Gazette 估算"52 个 ≥ $500K/年"是更准确的口径,需在档案中替换。

- **2026-06-05 Cluster 4 验证**(`subagent_tasks/cluster-4-ai-saas-api/result.md` §6.1):
  - **ai-translation-saas-niche-2026 引用 GetLatka "$820.8M 行业营收"**:GetLatka 是 Otter/Rev 等老牌 SaaS 收入汇总,非新入场 AI 翻译;**教训**:GetLatka 行业汇总页需谨慎,GetLatka 个人页才可信(本规则第 7 条白名单)。

- **2026-06-05 Cluster 3 验证**(`subagent_tasks/cluster-3-ai-agent-freelance/result.md` §7.1):
  - **本集群 10 个机会中 4 个机会的关键证据都是第二手引用**:AAA、Lead Gen、Red Team、One-Time、Vibe Coding 的关键证据(收入区间、案例数据、行业报告)都是 Medium 引"某报告"、Greensighter 引"某 IH 帖"、Mitrix 引"某 Gartner"。
  - **建议**(本规则吸收):"现实数据奖励"中的"月入 $1K+ 真实案例"必须是**第一手**(作者本人公开复盘),不是 Newsletter 二手汇总。

- **2026-06-05 Cluster 6 验证**(`subagent_tasks/cluster-6-platform-marketplace/result.md` §6 规则 4):
  - **Telegram Mini App 档案"500-member 群 $8K-12.5K MRR"是 GramBase 文章里的举例**,不是具体可验证 case;严格按 002 v2.0 规则,这种"行业估算"应该给 +0.5 而不是 +0.8。**教训**:二手汇总源"举例"类数字不可作为 +0.8 案例。
